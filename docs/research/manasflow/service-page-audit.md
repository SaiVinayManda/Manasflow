# Service and ecosystem route audit

Audit date: 27 October 2026.

## Gap found

- All 38 requested root-level agency, CRM, and service pathnames were missing as exact routes.
- The existing `/agency/[...slug]` page redirected every agency destination to `/services`.
- The 45 existing service-detail entries were reduced to generic content because their source pages stream the meaningful content after the initial `<main>` loading shell.

## Implementation

- Added 38 explicit root page files, each with a full title, description, canonical, Open Graph, and Twitter metadata generated by the shared metadata helper.
- Added a shared service renderer and 64 page records: 19 agency/CRM pages plus all 45 source service pages. The registry supplies 480 sections and 638 native FAQ disclosures.
- The renderer preserves source split/centered hero variants, hero bullet panels, alternating two-column body sections, feature grids, numbered build processes, comparison tables, related links, and CTA structure with the existing ManasFlow design tokens.
- Restored 100 source figure slots with neutral code-native React/CSS/SVG diagrams. Their placement, left/right order, and 16:9, 1:1, or 21:9 aspect ratios come from the source markup. Architecture diagrams use source feature labels; problem diagrams contrast fragmented handoffs with a connected workflow; delivery maps use the source process steps and deliverables.
- Shared consultation uses the existing working email-request component; all booking/contact actions remain local or address info@manasflow.com.
- Removed source founder identities, personal media, original proprietary names, external booking services, client claims, and testimonial video components from these new pages.
- Source agency documents were fetched successfully from all 19 original source routes. Existing cached service documents supplied their actual streamed sections.

## Evidence and remaining visual differences

The source desktop agency hero was observed at 1280?672: a large left-aligned headline and CTA group, with an outlined right-side ?What we build? panel. Source classes declare a 1280px container, 1.1fr/0.9fr desktop grid, 72px heading, 88vh hero, and 96px body section spacing. Some core services use a centered 80vh hero.

The local hero uses the existing mountains image. Original body illustration PNGs are replaced in their original slots by neutral ManasFlow architecture, workflow, problem/solution, and delivery diagrams. Their artwork differs from the original illustrations while preserving their explanatory role and section geometry. Client logo strips and testimonial media are omitted from these new pages. Full pixel-level comparison of all 64 routes remains separate from the source-text, layout, type, route, and metadata checks; source motion timing and every minor responsive wrapping difference have not been individually compared.

## Checks completed

- Targeted ESLint for the shared service renderer and representative root page wrappers: passed.
- Full TypeScript check after service and model-directory integration: passed.
- `/n8n-agency`, `/salesforce-consultants`, `/ai-agent-development`: HTTP 200, proper titles, FAQ disclosures, multiple real sections, no original runtime brand matches.
- Original workflow and product links remain intact for the combined supplemental route registry.

## Registry API

- `ServiceLandingPage({ slug })`: render a complete service page.
- `servicePageByRoute(route)`: resolve requested root paths, original source paths, or `/services/<root-slug>` aliases.
- `servicePageMetadata(slug, route?)`: produce fully branded metadata for the requested canonical route.
- `SERVICE_PAGE_ROUTES` and `SERVICE_SOURCE_ROUTES`: route inventories for build generation, auditing, and sitemap integration.
